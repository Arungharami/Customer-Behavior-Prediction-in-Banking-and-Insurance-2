# Customer Behavior Prediction in Banking and Insurance - Part 2

## Research title

**Beyond Static Accuracy: Drift-Aware, Calibration-Safe, Explanation-Stable, and Cost-Sensitive Customer Behavior Prediction in Banking and Insurance**

This repository is the reproducibility package for a second-stage research study that extends a previously published applied customer-behavior framework. Part 2 is designed as a **new empirical study**, not a rewrite of Part 1.

The core question is no longer only "Which model has the highest AUC?" It is:

> **Which financial prediction system remains accurate, calibrated, explainable, computationally efficient, and economically useful when customer populations and operating conditions change over time?**

## Scientific contribution

The project evaluates predictive performance together with five deployment properties that are often omitted from customer-behavior studies:

1. **Temporal stability and drift** - performance by time window, Population Stability Index (PSI), distribution shift, and the Home Credit stability metric.
2. **Probability calibration** - Brier score, Expected Calibration Error (ECE), reliability diagrams, calibration slope/intercept, and post-hoc Platt/isotonic calibration.
3. **Explanation stability** - SHAP global/local explanations plus cross-window rank stability (Spearman correlation and top-k Jaccard overlap).
4. **Operational decision value** - cost-sensitive thresholds, fixed-capacity evaluation, net benefit, Recall@Top-k%, and decision-curve style analysis.
5. **Complexity and reproducibility** - training time, inference latency, peak memory, serialized model size, deterministic seeds, environment lock, and artifact manifests.

## Public benchmark datasets

The study is designed around public financial datasets with transparent provenance. Raw competition data are **not committed to GitHub**.

### A. Home Credit - Credit Risk Model Stability (primary temporal benchmark)
Kaggle competition: `home-credit-credit-risk-model-stability`

Why it is central: the competition explicitly evaluates default prediction with performance stability over time. It is the primary benchmark for the drift/stability contribution.

### B. UCI Bank Marketing (banking behavior / product uptake)
Kaggle mirror or UCI source. The full data contain 45,211 observations and are ordered by date from May 2008 to November 2010. The target is term-deposit subscription.

### C. Porto Seguro Safe Driver Prediction (insurance claim propensity)
Kaggle competition: `porto-seguro-safe-driver-prediction`

The target is whether a driver initiates an auto-insurance claim in the following year. This provides a real insurance-domain external-validation benchmark.

### Optional D. IEEE-CIS Fraud Detection
Kaggle competition: `ieee-fraud-detection`

Use only as a supplementary fraud stress test if computational resources and manuscript word limits permit.

## Models

Required baselines:
- Logistic Regression
- Random Forest
- XGBoost
- LightGBM
- CatBoost

Advanced/optional:
- calibrated gradient boosting
- stability-aware weighted ensemble
- TabPFN/modern tabular foundation model on resource-feasible subsets as an exploratory benchmark

The paper must not claim that a more complex model is superior unless the gain remains meaningful after latency, model-size, calibration, and cost comparisons.

## Evaluation matrix

Every reported result must be produced by executable code and saved under `artifacts/`.

| Dimension | Required metrics |
|---|---|
| Discrimination | ROC-AUC, PR-AUC, F1, precision, recall |
| Calibration | Brier, ECE, calibration slope/intercept |
| Temporal stability | window AUC/PR-AUC, stability slope, PSI, drift alerts |
| Explainability | SHAP importance, rank Spearman, top-k Jaccard |
| Operations | Recall@Top-k%, precision@capacity, expected cost/net benefit |
| Efficiency | train time, p50/p95 inference latency, model size, peak RAM |
| Uncertainty | bootstrap 95% CI; optional conformal risk sets |

## Hard research rules

- **No fabricated data, metrics, figures, citations, or runtime results.**
- Approximate values may appear only in planning documents and must never be presented as experimental findings.
- Kaggle competition data remain subject to the applicable competition rules and must not be redistributed here.
- Every manuscript number must map to a machine-readable result file.
- Every figure must be generated by code, numbered sequentially, cited in the text before/near its appearance, and registered in `docs/FIGURE_TABLE_REGISTRY.md`.
- The final blind manuscript must not contain author-identifying information.

## Reproducibility workflow

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Configure Kaggle API credentials locally; never commit kaggle.json.
python scripts/download_kaggle_data.py --dataset all

# Run the full experiment pipeline.
python -m src.pipeline --config config/research.yaml

# Validate that every manuscript figure/table has a backing artifact.
python scripts/research_gate.py

# Export the best small model + model card bundle for Hugging Face.
python scripts/push_to_huggingface.py --dry-run
```

## Publication gate

The manuscript is submission-ready only when all of the following are true:

- all datasets are documented with provenance and licenses/rules;
- temporal splits are fixed before model comparison;
- no leakage is detected;
- all metrics have 95% confidence intervals where appropriate;
- calibration and drift are reported, not only AUC;
- SHAP figures are generated from the exact reported models;
- training/inference/model-size comparisons answer the complexity concern;
- all figures/tables are sequential and referenced correctly;
- references are APA 7th edition and verified against original sources;
- the blind manuscript contains no identifying metadata;
- the repository commit hash and environment are recorded in the manuscript supplement.

See `docs/MASTER_RESEARCH_PROMPT.md` for the full execution prompt and `docs/PAPER_BLUEPRINT.md` for the publication architecture.
